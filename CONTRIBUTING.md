# Contributing Guidelines

Thank you for your interest in contributing to *nio-s3* project! 

Whether it is a bug report, a new feature, a correction, or additional documentation, every contribution is welcome. Please read through this document before submitting any issues or pull requests.

## Reporting Bugs and Feature Requests

Use the GitHub issue tracker. Before opening a new one, please check [existing open](../../issues) or [recently closed](../../issues?q=is%3Aissue+is%3Aclosed) issues to avoid duplicates.

When filing a bug report, please include:

- Java version and operating system
- Steps to reproduce the problem
- Expected result vs actual result
- Relevant stack traces or logs

## Contributing via Pull Requests

Your ideas and suggestions are welcome! Pull request is the best way to contribute. To send a pull request:

- Make sure the same problem has not already been recently analyzed and resolved in other issues or pull requests
- Open an issue to discuss about them before investing a lot of time and effort into the implementation
- Fork the repository and create a branch from `main`
- Use [seven rules](https://cbea.ms/git-commit/#seven-rules) when comment a commit
- Do not change code that is not strictly related to the problem you are trying to help solve
- Make sure the code of your branch compiles with the target Java version
- Make sure your code is covered by unit and integration tests
- Use LocalStack for integration tests to avoid using real AWS credentials

## Local Configuration

Be sure to have a JDK 21+, Maven 3.9.x and Docker locally installed. Integration tests run on **LocalStack 2026.3.0**. Unfortunately, starting from this version, creating an account and obtaining a token is required in order to access the service. The token must be configured as an environment variable. Therefore, the following steps are mandatory to work with this version:

- Sign up [here](https://app.localstack.cloud/sign-up) for free and get the token to access the server.
- Set the `LOCALSTACK_AUTH_TOKEN` environment variable to your token value

After the Run Configuration in your IDE is configured:
- Run `mvn clean install` to build the project
- Run `mvn test` to run only unit tests
- Run `mvn failsafe:integration-test` to run only integration tests on LocalStack

Before starting to modify the code, apply the [formatting rules](./code-formatter.xml) adopted for this project in your IDE. The file was generated by Eclipse, but it can also be imported into IntelliJ.

## Security Policy

### Reporting a Vulnerability

If you discover a security vulnerability, please do **not open a public issue**. Instead, report it privately via GitHub Security Advisories or by contacting the maintainer directly.

Please include a clear description of the issue and steps to reproduce if possible. We will acknowledge the report and investigate it as soon as possible.

### Dependency Security

This project uses the AWS Java SDK and Jakarta APIs.

Security issues should be checked via [Security Bulletins](https://aws.amazon.com/security/security-bulletins/) or reported via [Vulnerability Reporting](https://aws.amazon.com/it/security/vulnerability-reporting/).
